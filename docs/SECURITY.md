# Security

Madkhal is advisory software with no connection to any plant system. It reads a pinned data
snapshot, computes, and serves read only results. Any future integration with an operator would
be read only and offline first (`docs/PILOT.md`).

## Threat model (STRIDE, for the API)

| Threat | Example | Mitigation |
|---|---|---|
| Spoofing | Someone serves a modified copy pretending to be the tool | Open source with tagged releases; the evidence snapshot is hash checked against `MANIFEST.json` at start up, and its events file matches the hash Nadhir itself recorded |
| Tampering | Altered snapshot or results files | Manifest hash check (fails loudly naming the file); results are regenerated by `madkhal eval` and a test fails if the rendered evaluation differs from them |
| Repudiation | An advisory is disputed later | Each advisory carries the SHA-256 of its inputs and its seed and can be reproduced exactly from stored inputs (test MK-L4-011) |
| Information disclosure | Server paths or secrets in responses | No secrets exist in the repository; responses never contain file system paths (test over every route); no personal data is processed |
| Denial of service | Large or costly requests | Request bodies capped at 64 KB; seeds, draws, dates, horizons, timeline windows (400 days) and mission sizes are bounded and validated; expensive computations are cached; the static demo needs no server at all |
| Elevation of privilege | Executing uploaded content | The API accepts no uploads and executes nothing supplied by a client; YAML is read with `yaml.safe_load` only; errors are `application/problem+json` without stack traces |

## Practices

* Dependencies are pinned in `requirements.lock.txt` and `web/package-lock.json`.
* `pip-audit` results are recorded below; a CycloneDX SBOM is produced by `madkhal all`
  (`sbom.json`, not committed).
* No secrets, keys or tokens are used or stored. `.env` files are ignored by git.
* The web app makes no request outside its own origin (tested in both modes).

## Dependency audit

`madkhal audit` runs `pip-audit` on `requirements.lock.txt` and `npm audit` on
`web/package-lock.json` and records both outputs, with the date, in `results/pip_audit.txt`
and `results/npm_audit.txt`; `madkhal all` runs it too.

During P10 the first web audit reported advisories in three packages: `maplibre-gl` (a
sanitiser bypass, rated critical; the map does not use popups or HTML from data), `react-router`
(open redirect, moderate) and `vitest` (development only). All three were upgraded to fixed
versions (`maplibre-gl` 6, `react-router-dom` 7, `vitest` 5), the web tests were run again,
and both audits then reported no known vulnerabilities. A later audit can differ, because
advisories are published continually; rerun `madkhal audit` before any use.
