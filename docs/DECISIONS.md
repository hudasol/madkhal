# Decisions log

Readings of the build brief where it was silent or ambiguous, and the reason for each.
Larger architectural decisions have their own ADR in `docs/adr/`.

| ID | Decision | Reason |
|---|---|---|
| D-001 | Requirements carry a `phase` field, and the fast check enforces "every MUST requirement has a test" only for phases already reached (`enforced_through` in `docs/requirements.yaml`). At v1.0.0 every phase is enforced. | The brief asks for `madkhal check` to pass on every commit and also for every MUST requirement to have a test. Both hold only if requirements of later phases are not enforced before they are built. The matrix marks them "not yet built" rather than hiding them. |
| D-002 | Web tests name requirement IDs inside their test titles (for example `it("MK-L8-002 banner ...")`); Python tests use `@pytest.mark.req("MK-...")`. One scanner reads both. | Keeps one traceability matrix across the Python and TypeScript halves. |
| D-003 | A claim of kind `url` resolves only if the page is listed in `docs/sources_opened.yaml` with the date it was opened. | Tests cannot fetch pages (no runtime network calls), so the register records which pages were actually opened during the build. |
| D-004 | "Observable" means at least 5 clear satellite days in the 121 day lookback at 50 km. | Reproduces Nadhir's own classification (3 observable, 2 not); any threshold from 2 to 20 gives the same split (ADR 0002). |
| D-005 | Events are shown with neutral labels written in the adapter (place, year, kind), never with Nadhir's `name` or `plants` fields, which name operators. The snapshot keeps Nadhir's text verbatim because it is hash checked data. The operator name scan excludes `data/nadhir_snapshot/`. | The brief says to name no operator in the UI or code, and also that places and documented events may appear as they do in Nadhir. Showing the place, date and evidence status satisfies both. |
| D-006 | Each event carries a short `status_badge` that must contain "UNVERIFIED" whenever any part of the verbatim status is unverified (enforced by the contract). The Fujairah 2008 to 2009 event shows "VERIFIED-SECONDARY, dates UNVERIFIED". | Its Nadhir status is verified for plant losses but unverified for dates; a coarse class alone would hide the unverified part. |
| D-008 | The acceptance test "nodata days never reduce the interval width" is tested as "a nodata day never moves the belief further from the seasonal prior" (total variation per draw). The requirement text MK-L2-009 states this openly. | Probing random histories showed the literal reading is false for a correct Bayesian filter in two ways: after alerts, blind days let the belief relax toward the seasonal prior and the interval shrinks; and a quiet clear day can give a wider interval than a nodata day because draws with different detector visibility react differently. Forcing the literal property would require a wrong filter. A test demonstrates the second case so the gap is visible. |
| D-009 | "More alerts never lower P(any bloom state)" is tested for the day the alert arrives (for every draw and any history). On later days an extra past alert followed by quiet clear days can leave a lower P(any bloom) than no alert; a test demonstrates this. | The alert marks the bloom as visible, and later quiet days refute a visible bloom quickly, whereas without the alert part of the belief stays on an invisible bloom that quiet days cannot rule out. This is the blind spot model working as intended. The decision layer's safety properties are stated on the belief it receives (P5). |
| D-010 | `docs/CONTEXT.md` cites the results release only for the reverse osmosis share. The brief's description that the release says ageing thermal units are reaching end of life is not cited, because that wording was not found in the text that was opened; the nearest statement (one cogeneration plant reconfigured to power only) is reported as found. | Only statements from pages actually opened may be cited. |
| D-011 | The second public source refused the page fetcher (HTTP 403) but served the PDF to a plain download; it was read from that download. | The brief allows citing only pages that were opened; the file was opened and read, so it counts as opened, and the route is recorded in `docs/sources_opened.yaml`. |
| D-007 | Snapshot bytes come from git blobs at the pinned commit, not from the reference clone's working tree. | The clone was checked out with CRLF conversion; blob bytes are platform independent and match the hash Nadhir itself recorded for `events.yaml`. |
| D-012 | Two properties were restated after the independent review (P10). (a) Dwell and hysteresis give way when the action in force and every more restrictive option breach a budget; the advice moves to the smallest relaxation within budget and NO SAFE OPTION is shown exactly when every option breaches (ADR 0008, amendment). (b) "A lower scale never raises fouling" is tested on the index capped at the hard limit and on the breach time, as the load test beside it already was. | (a) The original rule could say "every option breaches" when a safe option existed, which the brief forbids. (b) Hypothesis found inputs where both scales trip the plant and the lower scale trips ten hours later but overshoots the limit by 0.002 more in the tripping hour; the raw dose is not monotone at the trip boundary, while the safety relevant quantities are. Neither change loosens a threshold; both tests now state the property that holds and the counterexample is kept in the test comments. After (a) the experiments were run again in full: E1, E2 and E4 to E7 are byte identical; in E3 (G2) only the escalation days per year of P3 and P4 fell slightly (days that had wrongly shown NO SAFE OPTION), and no prediction changed. |
| D-013 | Claims CL-009 and CL-010 point to `docs/CONTEXT.md` instead of the source URLs, and `docs/sources_opened.yaml` no longer lists those pages. CONTEXT.md records each page with its address, publication date and opened date. This supersedes the route recorded under D-011. | The review found the organisation's name in a URL slug in the claims register, which is also shown on the Method screen. The build rules allow real names only in CONTEXT.md. The name scan is now case insensitive and has no URL exemption. |
| D-014 | Review finding rejected: "personal data in the README". The README keeps the author's LinkedIn link and email address. | The brief requires a contact section with exactly these details. The constraint "no personal data" concerns data the product processes; the product processes none. MODEL_CARD now says so precisely. |
| D-015 | Review finding accepted as a qualification, not a result change: dwell compliance in E6 (PR-E6-2) cannot fail in the daily lab. A note in `docs/evaluation_notes.yaml` says so; the dwell rule is tested by hourly property tests of the engine. | Results and predictions are never changed after the fact; a weak hit is qualified in the open. |
